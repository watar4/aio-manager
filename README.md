# AIO Manager — SEO / AIO / LLMO 診断サイト

URL を入力すると、AI検索(ChatGPT / Google AI Mode・AI Overviews / Perplexity / Copilot / Claude)からの**可視性スコア**と、**優先度付きの対策リスト**を出力する静的サイトです。ビルド不要・依存ライブラリなしで GitHub Pages にそのまま置けます。

判定基準・重み付け・推奨アクションはすべて **2026年に公開された一次情報／実証データ**に紐づけており、根拠は [`sources.html`](sources.html) で全件開示しています。

## このツールの考え方

一般的な「AIO診断ツール」と違う点は4つです。

1. **JavaScript を実行せずに評価する。**
   取得した生HTMLを `DOMParser` で解析するため、スクリプトは実行されません。これは制約ではなく仕様です — SMX Advanced 2026 で Sam Torres が報告したとおり **AIクローラーの69%はJavaScriptを実行できません**。つまりこの解析結果が「AIに見えているページ」そのものです。診断結果には「AIクローラーが見ているページ」として抽出本文をそのまま表示します。

2. **効果が確認されていない施策を加点しない。**
   `llms.txt` は検出しますが**加点しません**。2026年の実証で、全AIボット流入の0.1%(BrightonSEO 2026 / Thomas Peham)、有効な llms.txt の97%が当月一度もリクエストされず(Ahrefs、137,210ドメインのログ分析)、Google は非対応を明言しています。優先順位を誤らせないことを重視しています。

3. **測れない領域を「測れない」と明示する。**
   AI検索でのブランド言及の85%は第三者ソース由来です。この領域はURL単体では測定できないため、自動スコアとは分けて[オフサイト自己診断](checklist.html)で評価し、統合スコア(オンサイト60:オフサイト40)として提示します。

4. **1ページで終わらせず、サイト単位で見る。**
   トップページのURLを入れると配下ページもまとめて診断し(既定10ページ)、**「複数ページで同時に落ちている項目」**を集計します。共通テンプレート由来の課題は1回の修正で全ページに効くため、ここが投資効率の最も高い領域になります。

## 配下ページの選び方

検索APIはブラウザから直接叩けない(キーとCORSの制約)ため、「ドメインで検索したときの上位」を次の3つの信号で近似しています。

1. **sitemap.xml に載っている** — サイト側が収録を宣言したURL。並び順も重要度の手がかりとして使用
2. **トップページからリンクされている** — 内部リンクは重要度の主張そのもの
3. **グローバルナビに入っている** — サイト構造上の主要導線

加えて、

- カート・ログイン・マイページ・検索結果・PDF・ページネーションは除外
- 商品系(`/product`, `/item`, `/goods` …)と一覧・特集系(`/category`, `/feature`, `/topics` …)のテンプレートを優先
- 同じURLパターン(テンプレート)からは**最大2件まで**。商品詳細ばかり10件並ばないようにして診断範囲を広げる
- 起点と同じtitle・ほぼ同じ本文量のページには「起点と実質同一」を表示(重複コンテンツの検出)
- 取得に失敗したページはスキップし、レポート末尾に理由付きで記録

実際の検索順位とは一致しませんが、**サイトが自ら重要と位置づけているページ**を選ぶため、テンプレート単位の傾向を掴む目的では実用的な近似になります。処理中は「ここまでで中断する」で途中打ち切りができ、それまでの結果でレポートが作られます。

## スコア配分

|---|---|---|
| AI可読性(レンダリング) | 25 | AIクローラーの69%はJS実行不可(SMX Advanced 2026 / Sam Torres) |
| コンテンツ構造(RAG適合) | 20 | ファンアウトクエリのネットワーク管理(BrightonSEO 2026 / Dr Pete Meyers)、コンテキストグラフ(Dawn Anderson) |

独自チェックとして「**構造化データにしか書かれていない情報**」を検出します。Otterly AI の統制実験で「スキーマにのみ存在する情報は全プラットフォームが正しく回答できなかった」と示されたため、JSON-LD の値(価格・評点・ブランド名・住所など)が本文HTMLにも存在するかを照合します。

## GitHub Pages への公開

```bash
git init
git add .
git commit -m "AIO Manager: 初版"
git branch -M main
git remote add origin https://github.com/watar4/aio-manager.git
git push -u origin main
```

その後、GitHub の **Settings → Pages** で

- Source: `Deploy from a branch`
- Branch: `main` / `/ (root)`

を選択します。数十秒後に <https://watar4.github.io/aio-manager/> で公開されます。`.nojekyll` を置いているため Jekyll の処理は走りません。

## ローカルでの確認

ES モジュールを使うため `file://` では動きません。簡易サーバーを起動してください。

```bash
python -m http.server 4173
```

<http://localhost:4173/> を開きます。

## ページ取得について

GitHub Pages は静的ホスティングなのでサーバー側で外部URLを取得できません。そのため公開CORSプロキシ(AllOrigins / CodeTabs / corsproxy.io / isomorphic-git)を順に試すフォールバック構成にしています。

すべて失敗した場合(WAF や Cloudflare が外部プロキシを拒否している場合)は、**「HTMLを貼り付け」モード**に退避してください。ブラウザで対象ページを開き `Ctrl+U`(ページのソースを表示)→ 全選択 → コピーで取得できます。

> 開発者ツールの Elements パネルからコピーしないでください。そちらは JS 実行後の DOM であり、AIクローラーが見ているものとは異なります。

## データの取り扱い

診断履歴・プロンプト・観測記録・自己診断の回答は、すべて**利用者の端末の localStorage** にのみ保存されます。診断用のサーバーはなく、外部への送信はページ取得のためのプロキシ経由リクエストだけです。

## 技術構成

- 依存ライブラリなし・ビルドなし。ES モジュール + 素の SVG/CSS
- ライト/ダークテーマ両対応(OS設定 + 手動トグル)
- **レスポンシブは 320 / 360 / 414 / 640 / 768 / 900 / 1024 / 1280 / 1440px の全幅で検証済み** — 横スクロール・要素のはみ出し・要素同士の重なりがいずれもゼロであることを、4ページすべてで自動チェックしています
- UIのアクセント色(ブランドのインディゴ)とチャートのデータ色は別トークンに分離。データ色は明度帯・彩度下限・色覚多様性下での分離・コントラストの各チェックを通過した値のみ(light `#4a3aa7`/`#eb6834`、dark `#9085e9`/`#d95926`)
- 棒の色でスコアを二重エンコードせず、判定はアイコン+ラベルで別チャネルに載せています。全チャートに表(テーブルビュー)を併設
- 取得先ページの文字列は必ずエスケープしてから埋め込み(HTMLが属性値に漏れない)
- キーボード操作対応(折れ線チャートは矢印キーで系列値を読めます)

## 注意

- スコアは公開された実証データから逆算した相対評価であり、各AIプラットフォームの内部的な評価値ではありません。
- 配下ページの選定は sitemap・内部リンク・グローバルナビからの推定で、**実際の検索順位ではありません**。
- 商品詳細ページがトップからリンクされておらず sitemap にも無い場合(一覧がJS描画のみのサイトなど)は選定されません。その場合は代表URLを直接入力して単独診断してください。
